> 2026-09-22 晚。M1 落地后经历 3 次重启 + 1 次刷新，本文记录真机上暴露的每一个问题与修法。
> 每条都写清「现象 → 根因 → 证据 → 修法」，便于复发时快速定位。

## 1. cordis 配置：绝不能读 `ctx.config`

- **现象**：点「设置」后 probe 返回 `{"ok":false,"error":"cannot get property \"config\" without inject"}`
- **根因**：cordis 对**未 inject 的属性访问直接抛错**，而且 `?.` 挡不住——异常抛在可选链求值之前（这一点与 JS 直觉相反，容易反复踩）
- **正解**：配置是 `apply()` 的**第二个参数**。证据：`dsh-better-sidebar/src/index.ts` 写的是 `export function apply(ctx: Context, config?: SidebarConfig)`
- **改动**：`apply(ctx, config)` 接收 → `handleProbe(ctx, res, cfg)` / `handleExplain(ctx, req, res, cfg)` 传参，共 6 处
- **附注**：要探测服务一律走 `ctx.get('name')`（返回 undefined 不抛）

## 2. Message 缺必需字段（重启前主动查到，未爆出）

- **现象**：无（在重启前读源码时发现，避免了白费一次重启）
- **根因**：`Message` 要求 **id / role / content / source** 四个字段，初版只写了 role + content
- **证据**：`dsh-llm/lib/typert.host.js` 的 `Message` 声明；以及 `createMessage(input)` 的实现：
  ```js
  function createMessage(input) { return freezeMessage({ ...input, id: brandString(randomUUID()) }) }
  function brandString(value) { return value }   // ← 恒等函数
  ```
  官方工厂 `createUserMessage` 与手写对象**逐字段等价**（`brandString` 在运行时是 no-op）
- **改动**：`buildUserMessage()` 用 `randomUUID()` + `source: { kind: 'user' }`，文本块为 `{ type: 'text', text }`
- **为什么不用工厂**：`@deepseek-ai/dsh-llm` 从已安装插件目录解析不到（`ERR_MODULE_NOT_FOUND`，与 `dsh-home-paths` 同一陷阱）

## 3. 推理分片被当成回答渲染（用户报告）

- **现象**：浮窗里出现「一大长段辅助上下文」，与模型回复混在一起
- **根因**：宿主流式分片里**推理与回答都带 `text` 字段**。初版抽取是「看到 text 就要」，于是把模型的私有推理渲染成了回答——而推理必然逐条复述注入的整段辅助上下文与系统规则
- **证据**（真机实测 `done.chunkShapes`）：
  ```
  type,index,blockType   ← 声明 index 这一块是什么
  type,index,text        ← 增量文本（只带 index）
  type,index,block / type,usage / type,reason
  ```
  块类型在**独立分片**里声明，后续文本分片只带 index —— 所以必须按 index 追踪，光看 text 字段永远分不开
- **改动**：`createChunkReader()` 维护 `Map<index, kind>`，只渲染 `text` 块；**kind 未知时保守当回答**（宁可多显示一行，也不吞掉答案）
- **附注**：原始分片留样（前 8 个）进 `done.chunkSamples`，同类问题下次直接看证据
- **验证**：history.jsonl 里「GitHub」那条的 answer 无 `我们需要回答` / `不要复述问题` / `插件上下文` 等任一推理关键词

## 4. markdown 未渲染（用户报告）

- **现象**：`**加粗**`、编号列表原样显示
- **根因**：M1 刻意用 `white-space: pre-wrap` 纯文本呈现（PLAN §12.4 记录的取舍）
- **正解**：用宿主**共享**渲染组件，不自己写
  ```
  @deepseek-ai/dsh-client-ui-primitives → MarkdownText({ text, streaming, labels, fileMentions, pathImages })
  labels 只需：code.copyLabel / code.copiedLabel / footnotes
  ```
- **为什么用它**：GFM + TeX + Shiki；`streaming: true` 会冻结已完成块、按已完成行推进未闭合代码栅栏；**宿主自己的消息就用它渲染**，观感天然一致
- **改动**：`createAnswerView()` —— 优先 React 挂载 `MarkdownText`（rAF 节流，一个回答有数百个 delta），取不到宿主组件时回退纯文本
- **验证**：用户确认正常；bundle rev `34cc6fd281da → c067eabf0a29`，新 CSS 生效，console 无回退警告
