## 2. 一处计划外修正：零依赖化

原计划用 `@deepseek-ai/dsh-home-paths` 定位 DSH home。实测结论：

```
从 C:\Users\<user>\Documents\dsh\plugins\dsh-loupe 解析该包
→ ERR_MODULE_NOT_FOUND
```

它只存在于 `plugins/.vendor/node_modules`，而 Node 的上溯查找路径是逐级 `node_modules`（`plugins/node_modules`、`dsh/node_modules`、`Documents/node_modules` 均不存在），因此**解析不到**。若 dsh 加载器不做特殊解析，host 半端整个挂载失败。

**改法**：自实现 `dshHome()` —— `DSH_HOME` 环境变量优先，否则 `os.homedir()/.dsh`。`peerDependencies` 收窄为只剩 `@deepseek-ai/cordis`。**host 半端现在只 import `node:fs` / `node:os` / `node:path`**，不解析任何第三方包，不依赖加载器的解析策略。

## 3. M1 已落地

**`lib/index.js`（host）**

- `GET /plugins/dsh-loupe/probe` —— 能力诊断：llm 服务是否可达及其键名、provider/model 的完整解析链路（config → agentDefaultModel 服务 → settings.yaml）、context.md 是否存在/大小/预览、loupeDir 实际路径、配置快照
- `POST /plugins/dsh-loupe/explain` —— SSE 流式，事件：`meta`（模型与注入统计）/ `first`（首字延迟）/ `delta` / `done` / `error`
- 同源围栏（带 Origin 时必须与 Host 同源）；body 上限 512KB；选区/提问/所在消息各自截断；浏览器断开即 `AbortController.abort()`
- 三级模型解析：插件 config → `agentDefaultModel` 服务（多种形态试探）→ 解析 settings.yaml 的 `agent-default-model` 块（无 yaml 依赖，正则提取），每一级的尝试结果都进 probe 的 `tried[]`

**`lib/client.js`（client）**

- 选区探测：限定 `[data-chat-flow]` 内，排除输入框/textarea/contenteditable 与自家 UI（`[data-dsh-loupe]`）
- 浮标：选中即弹，锚在选区下方（越界时翻到上方），两个入口「解释」「设置」
- 浮窗：单实例、可拖拽、位置记忆（localStorage）、引用条显示选区、输入框预填提问句、多轮追加、流式渲染、底部注入统计行
- 设置面板：M1 阶段即诊断面板（拉 `/probe` 并原样展示 JSON）
- 清理：所有监听器进 `disposers`，`ctx.effect` 里统一拆除

**装机**：`dsh plugin --profile web add link:…` —— `dependencies` 与 `dsh.profile.bundles` 均已核对到位。

## 4. M1 的两个已知取舍

1. **输入框不重复选区文字**。PLAN 原文是"输入框默认填入所选内容和提问句"，实现为"引用条显示选区 + 输入框预填提问句"，避免同一段文字在 prompt 里出现两次。若要求输入框内也带选区原文，改一行。
2. **M1 不做 markdown 渲染**。流式回答以 `white-space:pre-wrap` 纯文本呈现。接宿主 markdown 组件放 M2。
